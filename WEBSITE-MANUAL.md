## Section 11 — Logging In

### What it is
The Admin Dashboard is the backend control panel where authorised staff manage all website content, view applications, and configure site settings.

### How to access
1. Open your browser and go to: `http://yourdomain.com/admin`
   - Local development: `http://localhost:3000/admin`
   - Docker local: `http://localhost/admin`
2. You will be redirected to the login page: `/admin/login`

### Logging in
1. Enter your **Email address** (default: `admin@iciitp.ac.in`)
2. Enter your **Password**
3. Click **Sign In**
4. On success you are redirected to the Admin Dashboard

### If you are locked out
- After multiple failed attempts, wait 15 minutes before trying again
- If you have forgotten your password, an admin with server access must:
  1. Set `ADMIN_FORCE_RESET=true` in `config/.env`
  2. Restart the backend
  3. Set it back to `false`
- The password is reset to the value of `ADMIN_PASSWORD` in `config/.env`

### Security notes
- Do not share admin credentials
- Always log out after your session using the logout button (top right of dashboard)
- The session expires automatically after 15 minutes of inactivity — you will be asked to log in again

## Section 26 — Docker Deployment (for hosting)

### Requirements
- Docker Desktop (or Docker Engine on Linux server)
- The project folder with `config/.env` and `data/db-dump.sql`

### First-time deployment
1. Copy the project to your server
2. Navigate to the project folder in terminal
3. Create the environment symlink:
   ```
   ln -sf config/.env .env
   ```
4. Edit `config/.env` — update `CORS_ORIGINS` to your domain, set `COOKIE_SECURE=true` if using HTTPS
5. Build and start:
   ```
   docker compose up --build -d
   ```
6. Restore the database (first time only):
   ```
   docker compose --env-file config/.env exec -T db psql -U iciitp -d iciitp < data/db-dump.sql
   docker compose --env-file config/.env restart backend
   ```
7. If restoring from a dump created before June 2026, run these manually after the restore (then restart backend):
   ```sql
   CREATE TABLE IF NOT EXISTS login_attempts (
       id           VARCHAR(255) NOT NULL PRIMARY KEY,
       ip           VARCHAR(255) NOT NULL,
       attempted_at TIMESTAMP(6) NOT NULL
   );
   CREATE INDEX IF NOT EXISTS idx_login_attempts_ip_time ON login_attempts (ip, attempted_at);
   ```
8. Site is live on port 80: `http://yourdomain.com`

### What persists across builds
- All database content (news, media, startups, events, notifications) — stored in `data/postgres/`
- All uploaded files — stored in `data/uploads/`
- Running `docker compose up --build` only rebuilds code — data is never touched

### Updating the code
```
docker compose up --build -d
```

### Stopping the server
```
docker compose down
```
> ⚠️ Never run `docker compose down -v` — this permanently deletes all database data

## Section 27 — Backing Up the Database

### Why it matters
Regular backups protect against accidental data loss. Take a backup before any major update or deployment.

### Taking a backup

**From local development:**
```
pg_dump -U iciitp --clean --if-exists iciitp > data/db-dump.sql
```

**From Docker:**
```
docker compose --env-file config/.env exec db pg_dump -U iciitp --clean --if-exists iciitp > backup-$(date +%F).sql
```

### Restoring a backup

**Into Docker:**
```
docker compose --env-file config/.env exec -T db psql -U iciitp -d iciitp < data/db-dump.sql
docker compose --env-file config/.env restart backend
```

### Recommended backup schedule
- Before every deployment / code update
- Weekly during active use
- Before adding large amounts of content

## Section 28 — Common Issues & Fixes

### Admin logs out on every page (Docker)
**Cause:** `COOKIE_SECURE=true` but site is running on HTTP (no SSL)
**Fix:** Set `COOKIE_SECURE=false` in `config/.env`, then rebuild:
```
docker compose up --build -d
```

### Cannot log in — wrong credentials
**Fix:** Check `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `config/.env`

### Admin password forgotten
1. Set `ADMIN_FORCE_RESET=true` in `config/.env`
2. Restart backend: `docker compose --env-file config/.env restart backend`
3. Log in with the password in `ADMIN_PASSWORD`
4. Set `ADMIN_FORCE_RESET=false`

### Media / news not showing in Docker
The database needs to be restored from the dump:
```
docker compose --env-file config/.env exec -T db psql -U iciitp -d iciitp < data/db-dump.sql
docker compose --env-file config/.env restart backend
```

### Port 80 already in use
Find and stop what is using port 80:
```
sudo lsof -i :80
sudo kill -9 <PID>
```

### DB container unhealthy on startup
The `.env` symlink may be missing:
```
ln -sf config/.env .env
docker compose up -d
```

### Frontend shows old content after update
Clear the Next.js cache by rebuilding:
```
docker compose up --build -d
```

### Uploaded file not showing on public site
1. Check the file exists in `data/uploads/`
2. Check the media record exists in the Media Library
3. Check Nginx is running: `docker compose --env-file config/.env ps`
